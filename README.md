# MTR Optimization Addon (Fabric 1.19.4)

Клиентский аддон для **Minecraft Transit Railway 4.0.5** (Minecraft 1.19.4, Fabric).
Переносит в MTR 4 те идеи оптимизации из мода MTR-34, которые имеют смысл в архитектуре MTR 4.

## Что делает

| Параметр (`config/mtr_opt.json`) | По умолчанию | Что меняет в MTR 4 |
|---|---|---|
| `maxRailRenderDistanceBlocks` | 192 | Потолок дальности отрисовки рельсов (`RenderRails.renderWithinRenderDistance`). 0 = как в MTR |
| `maxOcclusionRadiusChunks` | 16 | Радиус occlusion culling в рабочем потоке (в MTR зашито 32). 0 = как в MTR |
| `workerThreadSleepMillis` | 0 | Пауза рабочего потока culling (в MTR зашито 10 мс). 0 = как в MTR |
| `nodeCheckRadiusBlocks` | 8 | Радиус проверки «висящих» узлов при предмете рельсов в руке. В MTR 16, то есть 35 937 вызовов `getBlockState` за кадр; при 8 их 4 913 |
| `dynamicTextureLifetimeMillis` | 0 | Время жизни динамических текстур (названия станций, знаки, табло). В MTR 10000 мс |
| `vehicleModelCacheMillis` | 300000 | Сколько минимум хранить собранные модели поездов, тележек, объектов и рельсов после последнего обращения. В MTR 60000 мс; после этого модель собирается заново, когда поезд снова попадает в поле зрения. Больше значение = меньше «выпрыгиваний» и подтормаживаний, но больше занятой памяти |
| `fastStringFormat` | true | MTR 4 каждый кадр собирает строки через `String.format`: ключи текстур знаков, названий станций и табло (`DynamicTextureCache`, 12 методов), пути текстур дверей перронов (`RenderPSDAPGDoor`), табло (`RenderPIDS`) и панели лифтов. Аддон подменяет это быстрой версией с тем же результатом (только `%s`; любые другие шаблоны идут в настоящий `String.format`). Меньше мусора для GC, меньше микрофризов |
| `resourceTextCacheMaxEntries` | 0 | Ограничение текстового кэша ресурсов MTR (`CustomResourceLoader.RESOURCE_CACHE`): там до перезагрузки ресурсов лежит текст всех прочитанных json моделей и свойств. 0 = не трогать (по умолчанию). Для экономии RAM ставьте 256-512; плата за это: лишние файлы при необходимости читаются заново |
| `arrivalsRefreshMillis` | 0 | Период запросов прибытия поездов для табло. В MTR 3000 мс; больше значение = меньше пакетов, но данные старее |

## Готовые профили

Меняйте значения в `config/mtr_opt.json` (после правки нужен перезапуск игры).

| Профиль | maxRail | occlusion | nodeCheck | textureLifetime | modelCache | textCache | arrivals |
|---|---|---|---|---|---|---|---|
| По умолчанию | 192 | 16 | 8 | 0 | 300000 | 0 | 0 |
| Слабый ПК / меньше RAM | 128 | 8 | 6 | 5000 | 0 | 256 | 5000 |
| Много RAM, максимум плавности | 256 | 24 | 8 | 30000 | 900000 | 0 | 0 |

(0 в `modelCache`, `textureLifetime`, `arrivals` значит «как в MTR»; в профиле «Слабый ПК» модели хранятся по правилам MTR, то есть 60 с.)

## Что ещё помогает (настройки самого MTR и Java)

- В настройках MTR: «скрывать полупрозрачные части» (`hideTranslucentParts`) уменьшает нагрузку на рендер; «разрешение динамических текстур» (`dynamicTextureResolution`) держите на минимуме, он задаёт потолок размера текстур знаков и табло (2048 * 2^значение).
- Не выделяйте Java лишнюю память: большой `-Xmx` увеличивает паузы сборщика. Для клиента с MTR обычно хватает 4-6 ГБ. Пример аргументов: `-XX:+UseG1GC -XX:MaxGCPauseMillis=50`.

Каждый хук при первом срабатывании пишет в лог строку «Хук активен: ...»: по ней видно, какие миксины применились в вашей сборке MTR.

Конфиг создаётся при первом запуске клиента.

## Сборка

Нужен JDK 17.

```
./gradlew build
```

Готовый jar: `build/libs/mtr-opt-<версия>+mc1.19.4.jar`.
Кладётся в `mods/` вместе с Fabric API и MTR 4.0.5 для 1.19.4.

## GitHub

1. Создайте репозиторий и запушьте папку целиком.
2. Workflow `.github/workflows/build.yml` соберёт мод на каждый push и приложит jar как artifact.
3. Тег `v1.0.0` (`git tag v1.0.0 && git push --tags`) создаёт GitHub Release с jar.

## Важно

MTR как зависимость компиляции **не подключается**: миксины нацелены на классы MTR по строковому
имени (`@Pseudo`) и с `require = 0`. Если в вашей сборке MTR метод или константа отличаются,
конкретный миксин просто не применится, игра не упадёт (смотрите лог `mtr_opt`).

Подробности и список того, что не переносится и почему: [docs/PORTING_REPORT.md](docs/PORTING_REPORT.md).
